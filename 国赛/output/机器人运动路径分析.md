# 机器狗运动路径分析（当前导航代码 + 比赛地图）

## 1. 比赛地图对应关系

PDF 中第 2 页为 **大四足赛项** 地图，其功能区与你代码中的航点命名完全对应：

| 代码航点 | 地图功能区 |
|---|---|
| `obstacle_entry` → `obstacle_exit` | 地图底部“随机位置障碍”区域（锥桶/圆形障碍物） |
| `inspection_box_1_side_1/2`、`inspection_box_2_side_1/2` | 右侧两个“巡检箱”及其两侧的识别图 |
| `pick_area` | 右侧彩色柱状条/抓取区 |
| `place_A`、`place_B`、`place_C`、`place_D` | 顶部 A/B/C/D 四个投放区 |
| `start_exit`、`finish` | 起止区（通常在 A/B/C/D 附近或障碍区外侧） |

## 2. FSM 驱动的逻辑运动路径

`arm_grasp/arm_grasp/task_manager_node.py` 是总调度器，按以下顺序发布 `/waypoint/goal`：

```
start_exit
  → obstacle_entry
    → [开启 cone_avoidance] → obstacle_exit
      → inspection_box_1_side_1
      → inspection_box_1_side_2
      → inspection_box_2_side_1
      → inspection_box_2_side_2
        → pick_area
          → place_<异常区1>
          → pick_area
          → place_<异常区2>
            → finish
```

- 在 `obstacle_entry` 到 `obstacle_exit` 之间，代码开启锥桶避让，优先级高于普通航点导航。
- 检测完成后，只会对状态为 `abnormal` 的 A/B/C/D 区执行“抓取→投放”循环，最多 `max_abnormal_zones=2` 个。

## 3. 两种底层导航的行为

### 3.1 普通航点导航（`nodes/waypoint_navigator.py`）
- 订阅 `/camera_pose_fused`（SLAM + AprilTag 兜底融合位姿）。
- 收到航点名称后，向 `(x, y, yaw)` 做比例控制前进。
- 关键参数：`goal_tolerance=0.16`、`yaw_tolerance=0.22`、`max_vx=0.28`、`max_wz=0.45`。

### 3.2 障碍区局部规划（`cone_avoidance/local_planner.py`）
- 全局路径：`competition_map.yaml` 中 `global_path = [[0.2, 0.0], [5.8, 0.0]]`。
- 障碍区范围：`x∈[0, 6]`、`y∈[-1.5, 1.5]` 的矩形走廊。
- 速度：`normal_speed=0.15`、`slow_speed=0.08`、`max_turn_speed=0.25`。
- 行为：在走廊内沿 X 轴直线前进，遇到锥桶后通过 DWA 类候选速度评分（straight / left / right / crawl）绕行，离开障碍后回归全局路径。

## 4. ⚠️ 当前代码下实际无法运行出真实路径

`jetson_payload/slam_maps/waypoints_FINAL.yaml` 中所有航点坐标目前全部为：

```yaml
x: 0.0
y: 0.0
yaw: 0.0
```

`waypoint_navigator.py` 会把每个目标都解算到同一点 `(0, 0, 0)`。因此当前条件：
- 逻辑路径已经由 FSM 固定；
- 几何路径未定义，机器狗会反复尝试“到达”原点，无法按地图完成比赛。

3. 在 `dry_run=true` 模式下运行 `launch/guosai_final.launch.py` 验证 FSM 状态流转。
