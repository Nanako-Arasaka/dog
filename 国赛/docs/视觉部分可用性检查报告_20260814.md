## 二、已修复的问题(本次改动)

### 1.【P0 崩溃】HoughLinesP 结果索引跨 OpenCV 版本崩溃
- **位置**:`gauge_reader.py` L180、`src/perception/detector/fixed_detector.py` L656、`tools/gauge_reader.py` L234
- **现象**:代码用 `lines[:, 0, :]` 取线段,要求 HoughLinesP 返回 3 维 `(N,1,4)`。OpenCV 4.x 返回三维,但 **OpenCV 5.x 返回二维 `(N,4)`,直接 `IndexError` 崩溃**。本机调试即复现(已实测复现并定位到行)。
- **风险**:巡检主循环每帧调用 `read_gauge`,一旦崩溃整条巡检链路(40 分)直接挂掉。Jetson 上 OpenCV 4.x 未触发,但属于跨版本炸弹。
- **修复**:统一 `np.atleast_2d(np.asarray(lines)).reshape(-1, 4)`,兼容两代 OpenCV。修复后实测 4 组角度读准(30°→32.01、90°→88.06、210°→208.95、330°→329.98)。

### 2.【P1 误报】区域切换后旧仪表读数串台
- **位置**:`live_detect_yolo_opencv.py` 主循环(正式链路,config 指定)
- **现象**:检测到新 zone、但还没检测到新仪表盘时,`last_gauge_result` 仍是上一区域的读数,`should_publish_inspection()` 会把"新区域 × 旧读数"发布到 `/bridge/inspection_result` → 冻结器可能错误冻结。7 类版本(`live_detect.py`)有 zone 切换清空逻辑,5 类版本漏掉了。
- **修复**:`best_zone != last_zone` 时清空 `status_history`、重置 `unknown_counter` 和 `last_gauge_result` 为 unknown。

### 3.【P1 性能】gauge_reader 每帧无条件打印 DEBUG
- **位置**:`gauge_reader.py`(`_status_from_color_bands` 2 行 + `read_gauge` 2 行)
- **现象**:每个检测到仪表的帧打印 4 行日志,30fps 下每秒 100+ 行,刷屏 + 同步 I/O 拖慢主循环,现场日志被淹没。
- **修复**:改为环境变量 `GAUGE_DEBUG=1` 控制,默认静默。

### 4.【P2 兼容】YOLO 推理 device=0 硬编码
- **位置**:`live_detect.py` / `live_detect_yolo_opencv.py` 的 `predict_with_fallback`
- **现象**:固定 `device=0`(CUDA),无 GPU 环境(本机调试)直接抛异常。
- **修复**:`torch.cuda.is_available()` 自适应,`cuda:0` / `cpu`。

### 5.【P0 抓取 50 分】Astra 伪深度替换为真实深度(本次任务)
- **位置**:`arm_grasp/astra_camera_node.py`(重构)、`launch/guosai_final.launch.py`、`config/guosai_final.yaml`
- **旧问题**:深度图是常量 500mm 伪深度 + 近似内参,抓取位姿 z 方向不可靠。
- **新实现**:
  - 深度后端多级自动探测:`pyorbbecsdk`(官方 SDK,最可靠)→ UVC Z16 深度流(`/dev/video{camera_index+1}`,可配置 `depth_index`)→ 全失败则**不再发布深度**(安全,抓取侧报 `invalid_depth` 停止),不静默发假数据。
  - 新增参数:`depth_mode`(auto/pyorbbec/uvc/none)、`depth_index`、`fake_depth_fallback`(默认 **false**,仅调试用)。
  - pyorbbec 后端可用时自动从 SDK 读取真实相机内参替换近似值。
- **现场动作**:Jetson 上 `pip install pyorbbecsdk`;或确认 UVC 深度设备号后设 `depth_index`。装好后验证 `/rgbd_cam/depth/image_raw` 深度随距离变化、`/vision/grasp_pose` 的 z 不再恒 0.5m。

### 观察项(非 bug,不阻塞,供知悉)
1. **placement 门控是死代码**:`live_detect`(7 类/5 类)的 `/bridge/placement_zone` 发布受 `/task/status` 含 `WAITING_PLACE_ZONE` 门控,但正式 FSM(task_manager)从不发布该状态(仅 mock/测试工具里有)。→ 相机精对齐放置区实际不生效;正式流程靠导航航点对齐(FSM 回调仅观察,注释已说明)。若要启用:FSM 在放置阶段发布该状态,或设 `INSPECTION_PLACEMENT_ALWAYS=1`。
2. **arm_control 回调阻塞**:`_joints()` 在回调内 `time.sleep(duration+0.3)`,单线程 executor 下执行动作期间不响应其他回调。抓取/放置期间无其他必要输入,可接受。
3. **遗留链路已知项**:`fixed_detector`(vision_server 用)detect_gauges 硬编码 zone="A"、角度区间与 gauge_reader 不一致;cone 模型类别名 `item`≠`cone` 靠 class_id 兜底。均为非正式链路。
4. **generate_apriltags.py** 有 3 处 f-string 无占位符(打印时多余),无害。
