## ❌ 二、真正缺失：必须从外部获取

### 1. ORB-SLAM3 完整工程（定位核心，最大的缺口）⚠️ **无替代，必须补**

> ⚠️ **2026-08-17 更新：比赛规则禁用 AprilTag**，定位兜底方案（tag_localizer）已全部关闭。ORB-SLAM3 是**唯一**定位源——它缺失 = 没有位姿 = 狗完全走不了。此前报告中的"AprilTag 兜底可救导航"建议**作废**。

`controller/ORB_SLAM3/` 里**只有 C++ 源码**（`src/` 21 个 .cc/.cpp）和词汇表压缩包，缺少：

- ❌ `CMakeLists.txt` —— 仓库里没有，无法编译
- ❌ `Thirdparty/`（DBoW2、g2o、Sophus）—— 没有
- ❌ 编译产物 `build/libORB_SLAM3.so` —— 没有
- ❌ **ROS2 wrapper**（`ros2 run orbslam3 rgbd` 的 `orbslam3` 包）—— 整个仓库没有，但 `config/guosai_final.yaml` 的 orbslam3.command 依赖它

**处理方案（二选一）：**
```bash
# a) 从旧板整包拷贝（最快，推荐）
scp -r user@old_jetson:/home/jetson/ORB_SLAM3  ~/ORB_SLAM3

# b) 源码重新编译（30-60 分钟）
git clone https://github.com/UZ-SLAMLab/ORB_SLAM3.git ~/ORB_SLAM3
cd ~/ORB_SLAM3 && chmod +x build.sh && ./build.sh
# 另需 ROS2 wrapper: https://github.com/zang09/ORB-SLAM3-ROS2
```
（一键脚本 `scripts/setup_new_board.sh --build-orbslam3` 可自动执行方案 b）

### 2. OpenNI2 Redist 运行库（机械臂 Astra 深度相机）

- ❌ 仓库内完全没有 OpenNI2 相关文件（已全局搜索确认）
- 机械臂深度抓取依赖它（`astra_camera_node` 的 openni 后端）
- **处理**：手动下载 `OpenNI_2.3.0.66` 官方包，提取 Arm64 版，解压到 `~/openni2/OpenNI-Linux-*/Redist`（详见 `docs/Astra深度修复全记录与排障手册.md`）

## ⚠️ 三、仓库有文件，但需部署/生成/修复

### 3. ORB 词汇表 `ORBvoc.txt`（139MB）未解压

仓库只有 `ORBvoc.txt.tar.gz`（42MB），config 的 `vocabulary_path` 指向解压后的 `ORBvoc.txt`。
→ 一键脚本自动解压；或手动 `tar -xzf controller/ORB_SLAM3/Vocabulary/ORBvoc.txt.tar.gz -C controller/ORB_SLAM3/Vocabulary/`

### 4. `config/guosai_final.yaml` 的 4 处路径指向旧板（全部失效）

| 配置项 | 当前值（旧板路径） | 仓库内正确候选 |
|---|---|---|
| `slam.map_path` | `/home/jetson/Desktop/guosai/slam_maps/guosai_rgbd_map_v4.osa` | `jetson_payload/slam_maps/guosai_rgbd_map_FINAL.osa` |
| `slam.settings_yaml` | `.../guosai_realsense_rgbd_localization_v4.yaml` | `jetson_payload/slam_maps/guosai_realsense_rgbd_FINAL.yaml` |
| `slam.waypoints_yaml` | `.../waypoints_FINAL.yaml` | `jetson_payload/slam_maps/waypoints_FINAL.yaml` |
| `vocabulary_path` | `${GUOSAI_ROOT}/controller/ORB_SLAM3/Vocabulary/ORBvoc.txt` | 同路径（解压后即有） |

→ 一键脚本会在结束时检查并提示；也可手动运行：
```bash
python3 scripts/repair_guosai_final_config.py --config config/guosai_final.yaml --root $(pwd) --dry-run   # 预览
python3 scripts/repair_guosai_final_config.py --config config/guosai_final.yaml --root $(pwd)            # 写入
```
> ⚠️ **注意 repair 脚本的坑**：它会重写 `orbslam3.command` 为 **3 个位置参数**（vocab + settings + atlas），但 `config/guosai_final.yaml` 现有命令是 2 参数版，且 README 明确警告"**不要传第 3 个 .osa 参数**（会被误当 session 文件导致 pose 恒为 0）"。建议：**手动改 4 处路径，不要用 repair 重写 command**；若用 repair，改完检查 `orbslam3.command` 是否仍为 2 参数。
