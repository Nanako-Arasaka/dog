> 顶视图来自用户上传图：`24de35e33243495e14b475a80651a286.jpg`
> 用途：定位 10 个 AprilTag 备选贴附位置，与 FSM 航点的对应关系供后续模型理解。
> 坐标系约定：图像方向近似顶视图，但**世界坐标方向需与 ORB-SLAM3 地图对齐后再使用**。

## 1. 场地整体结构

场地尺寸 **5000mm × 6000mm**（来自 `docs/技术文档_草稿.md`），5 个分区：

| 区 | 位置（图上） | 任务 |
|---|---|---|
| 出发/结束区 | 图像下方大圆角区 | 出发 + 终点 |
| 障碍区 | 中段横向条纹区 | 锥桶避障 |
| 检测区 | 左侧两个中圆角矩形 + 周边条纹 | 仪表巡检（4 个观察位） |
| 抓取区 | 右下中圆角矩形 | 高台抓取红色长条 |
| 放置区 | 右上 4 个小圆角矩形 | 把红条放进对应字母箱 |

## 2. 视觉元素 → 功能映射

| 视觉元素 | 含义 | 备注 |
|---|---|---|
| 黄色背景 | 整片通行区 | 5000×6000mm |
| 灰色大圆角矩形 | 仪表箱或抓取高台 | 物理 800×600mm 或 800×600×500mm |
| 灰色 4 格小矩形（右上） | 放置箱 A/B/C/D | 每个 500×500×500mm |
| **纵向**条纹区（点五/四/八/十/九） | 巡检观察位 / 抓取接近 / 放置接近 | 狗侧身停靠 |

⚠️ **条纹朝向不是装饰**：纵向 = 狗侧身走过，横向 = 狗正面穿过。

### 3.1 推断流量顺序

```
点一/二/三（出发） → 点六（障碍区入口）
                   → 点七（障碍区出口）
                   → 点四/五/八（仪表巡检，绕仪表箱1）
                   → 点九（接近抓取区）
                   → 抓取（机械臂）
                   → 点十（接近放置区）
                   → 放置（机械臂）
                   → 回到 点一/二/三（结束）
```

### 3.2 不确定项（需要用户/现场确认）

1. **点八** 紧邻仪表箱1 下方纵向条纹，可能属于「仪表箱1 的第三个观察侧」或「另一辅助观察位」。当前 FSM 配置只支持每个仪表箱 2 个观察侧（side_1/side_2），如要纳入需要扩展。
2. **点三** 在出发区左端。可能只是出发区的「远端路标」，并非 FSM 流程航点。
3. **点十** 在放置区左侧。是否所有 4 个字母箱都从这个位置接近，还是每个字母箱独立路径，需现场确认。

## 4. AprilTag 贴附建议

### 4.1 通用原则
- **尺寸**：A4 大小（≈ 21cm），2~3m 内可靠检测；越远需越大
- **朝向**：贴附面**正对狗的来向**，避免强光直射
- **高度**：与相机高度齐平（狗身上相机位置），便于 PnP 解算稳定
- **库选型**：DICT_6X6_250（10 个 ID 用绰绰有余），用 `tools/generate_aruco_markers.py` 生成
- **坐标系**：每个 tag 的 `world.{x,y,z,yaw_deg,pitch_deg,roll_deg}` 必须**在建图坐标系**下，用 `tools/calibrate_tags.py` 自动采

### 4.2 每个点的贴附位置与朝向（推荐）

| 点 | 推荐贴附位置 | 朝向 | 备注 |
|---|---|---|---|
| 点一 | 出发区右后侧墙面/立柱 | 朝西（朝向场地中心） | 出发时正对，容易采到 |
| 点二 | 出发区中央地面立牌或后墙 | 朝北 | 出发点容易采到 |
| 点三 | 出发区左后侧墙面 | 朝东 | 收尾或中段路径上采到 |
| 点四 | 仪表箱1 右侧墙面（观察位正对面） | 朝东 | dog 停在 点四 位置时相机正对 |
| 点五 | 仪表箱1 左侧墙面 | 朝东 | 与点四形成两视角备份 |
| 点六 | 障碍区入口左侧墙面 | 朝东 | 穿过锥桶前最后能采到的位置 |
| 点七 | 障碍区出口右侧墙面 | 朝西 | 出锥桶后立即可校正位姿（最关键！） |
| 点八 | 仪表箱1 下方地面立牌 | 朝北 | **贴附方式待确认**（地面立牌是否合规） |
| 点九 | 抓取区上方立柱 | 朝西 | 接近抓取时校正 |
| 点十 | 放置区左侧墙面 | 朝南 | 接近放置箱时校正 |

### 4.3 优先级（最该先贴的）

按「**最容易丢定位且 tag 找回后收益最大**」排序：

1. **点七**（障碍区出口）—— 上一轮已经分析过，cone 策略漂 >0.16m 后永远到不了 obstacle_exit；在这里贴一张等于兜住最大风险
2. **点五/四**（仪表巡检侧）—— 巡检是长时间低速运行，容易因姿态变化跟丢
3. **点一**（出发点）—— 起步阶段最关键，SLAM 初始帧不稳
4. **点九**（抓取接近）—— 抓取需要绝对位姿精对齐
5. 其他按现场时间补

## 5. 关键约束（每一步都不能忘）

1. **坐标系锁定**：tag 的世界坐标 = 建图那次 ORB-SLAM3 的世界坐标。**重新建图 ⇒ 所有 tag 坐标作废**。所以地图必须一次性建好永不重建。
2. **/camera_pose 协议**：tag_localizer_node 输出 `/tag_localizer/pose`（独立话题），由 watchdog 仲裁融合后输出 `/camera_pose_fused`。下游（waypoint_navigator）改订阅 `/camera_pose_fused`。SLAM 原始 `/camera_pose` 不动。
3. **过渡跳变**：从 SLAM 切换到 tag（或反向）会有 0.1~0.5m 跳变，watchdog 仲裁期间需临时抑制 jump 检测 2~3s，避免恢复被自己人打死。
4. **检测距离**：A4 tag 在 2.5m 外识别率下降明显。建议每个点贴的位置保证 dog 在该路径段**最远 2m 内**能采到。
5. **多 tag 同时可见**：狗在某些路径上可能同时看到两个 tag（点四/五之间，点九/十之间）。node 应选**最近的一个**作为主，避免两个 tag 坐标不一致时来回跳。

## 6. 与 FSM 13 个航点的关系

FSM 当前有 13 个航点（来自 `config/guosai_final.yaml:115-127`）：

```
start_exit, obstacle_entry, obstacle_exit,
inspection_box_1_side_1, inspection_box_1_side_2,
inspection_box_2_side_1, inspection_box_2_side_2,
pick_area, place_A, place_B, place_C, place_D, finish
```

10 个定位点与 13 个航点的潜在映射：

| 10 点定位 | 13 航点 | 关系 |
|---|---|---|
| 点一/二/三 | start_exit / finish | 一个起一个收 |
| 点六 | obstacle_entry | 一一对应 |
| 点七 | obstacle_exit | 一一对应 |
| 点四/五 | inspection_box_1_side_1/2 | 一组（但图上只看见 1 个仪表箱的 2 个观察侧） |
| 点八 | inspection_box_2_side_1/2 之一种 | 推断属于仪表箱2 |
| 点九 | pick_area | 抓取接近 |
| 点十 | place_A/B/C/D 之一种 | 放置接近 |

⚠️ **未对上的**：图上只能看到 1 个明确的「仪表箱」（右上中圆角），但 FSM 有 2 个仪表箱（每个 2 个侧）。**图中底部那两个中圆角矩形可能分别是仪表箱2 和抓取高台**——这一点与第 3.2 节不确定项一致，需现场确认。

## 7. 后续模型接手须知

1. 这个图是**用户口述意图**，不是精确测绘。贴 tag 前必须用 `tools/calibrate_tags.py` 在真实场地上采实际坐标。
2. tag 物理贴附位置**不必与本图点位置完全重合**，只要是「狗能看见、且能覆盖 SLAM 高风险路径」的位置就行。
3. 如果用户后续给出更精确的布局图（带尺寸、坐标系），本文档会被覆盖。
4. 详见 `docs/航点采集现场操作指引.md` 与 `docs/QWEN_WAYPOINT_COLLECT_PROMPT.md` 中的 SLAM 验证步骤。
