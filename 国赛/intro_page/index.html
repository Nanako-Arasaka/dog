01

国赛现场要解决的工程问题

从比赛任务书和现场部署条件抽象出来的具体难点。

C1

巡检识别要稳定不能抖

比赛要求机器人逐区识别 A/B/C/D 四个区并判断 low / normal / high。单帧 YOLO 输出容易抖, 一旦提前把"还没看完"的局部结果发给机械臂, 就会出现"明明 A 正常却被抓红条"的低级失误。

4
区 · 全部冻结
C2

机械臂不能按时间松爪

任务流程是抓红条 → 走到放置区 → 识别到目标字母 → 松爪。 固定时长松手会让红条掉在错误的位置上; 必须让机械臂任务状态机把放置区识别结果 当成触发条件,而非定时器。

2
ROS2 同步点
C3

Lite2 狗端算力不够

Lite2 本体不适合跑 YOLO、OpenCV 读表、ORB-SLAM3、复杂 ROS2 状态机。 必须把所有感知与决策都下沉到 Jetson, 狗端只接 vx / vy / wz 或 Lite2 原生命令, 并保留 watchdog 超时停机。

3.1 · MODULE

Live Inspection (YOLOv8 + OpenCV)

实时巡检识别
FILE live_detect_yolo_opencv.py MODEL best.pt (YOLOv8n) CLASSES 7 RUNS CPU/GPU · Jetson
任务

主线脚本 live_detect_yolo_opencv.py 同时做两件事: 用 YOLOv8 自训权重(best.pt,5 类: zone_A/B/C/D + gauge) 定位画面中的巡检区, 裁出仪表盘 ROI 后调用 gauge_reader.read_gauge() 读指针角度, 输出 low / normal / high / unknown。

真实配置

CONF_THRES=0.25、IMG_SIZE=416、 CAMERA_WIDTH=640 / 480、 CAMERA_FPS=30、 STATUS_HISTORY_SIZE=7、 STATUS_STABLE_MIN_COUNT=4、 UNKNOWN_RESET_COUNT=5。

真实代码片段
live_detect_yolo_opencv.py · 识别循环 Python 
import cv2
from ultralytics import YOLO
from gauge_reader import read_gauge

model = YOLO("/home/jetson/yolo_deploy/best.pt")
status_history = deque(maxlen=7)
unknown_streak = 0

while True:
    frame = read_camera(4, w=640, h=480)
    dets = model(frame, imgsz=416, conf=0.25)[0]

    for box in dets.boxes:
        if box.cls in ZONE_CLASSES:
            zone = CLASS_NAMES[box.cls]   # zone_A/B/C/D
        elif box.cls == 4:                  # gauge
            roi = crop(frame, box)
            status = read_gauge(roi)      # low/normal/high

    # 7 帧滑动窗口, ≥4 帧一致才算稳定
    status_history.append(status)
    if status == "unknown":
        unknown_streak += 1
        if unknown_streak >= 5: status_history.clear()
    elif Counter(status_history)[status] >= 4:
        publish_inspection(zone, status)

3.2 · MODULE

InspectionFreezer + IntegrationBridge

状态冻结 + ROS2 转发
FILE integration_bridge/ ROS2 Humble · rclpy MSG std_msgs/String CLI --no-ros 模式
为什么需要

live_detect_yolo_opencv.py 会持续发布单帧结果。 如果直接转发,机械臂会在"A 还是 abnormal、C 还是 unknown" 的时候就被触发抓红条——这是现场最容易翻车的点。

冻结规则

InspectionFreezer(默认 stable_count=3) 要求每个区连续出现 3 次同样的状态才冻结。 全部 4 个区都冻结后,才向 /inspection/all 发布 最终字符串 A:abnormal,B:normal,...。

真实代码
inspection_freezer.py Python 
class InspectionFreezer:
    def __init__(self, stable_count=3):
        self.stable_count = max(1, int(stable_count))
        self._candidates = {}   # zone -> ZoneCandidate
        self._frozen    = {}   # zone -> InspectionResult

    def update(self, result) -> bool:
        if result.zone in self._frozen: return False
        if result.zone_state == "unknown": return False

        key = self._key(result)
        cand = self._candidates.get(result.zone)
        if cand is None or self._key(cand.result) != key:
            self._candidates[result.zone] = ZoneCandidate(result)
            return False

        cand.count += 1
        if cand.count >= self.stable_count:
            self._frozen[result.zone] = result
            return True      # 本次冻结
        return False
桥接节点关键逻辑

bridge_node.py 订阅 /bridge/inspection_result 和 /bridge/placement_zone, 经过冻结或直接转发, 发布 /inspection/all 和 /placement/recognized_zone。 同时通过 /inspection/reset(std_msgs/Bool) 支持现场一键重置。

bridge_node.py · 订阅与发布 Python 
class IntegrationBridgeNode(Node):
    def __init__(self):
        super().__init__("integration_bridge_node")
        self.freezer = InspectionFreezer(stable_count=3)
        self.create_subscription(String, "/bridge/inspection_result", self._on_inspection)
        self.create_subscription(String, "/bridge/placement_zone",    self._on_placement)
        self.create_subscription(Bool,   "/inspection/reset",          self._on_reset)
        self.create_publisher(String, "/inspection/all", 10)
        self.create_publisher(String, "/placement/recognized_zone", 10)
        self.create_publisher(String, "/competition/state", 10)

    def _on_inspection(self, msg):
        for r in inspections_from_payload(msg.data):
            if self.freezer.update(r):
                self.get_logger().info(f"zone frozen: {r.zone}:{r.zone_state}")
        if self.freezer.is_complete() and not self.frozen_text:
            self.frozen_text = self.freezer.frozen_text()
            self.pub_inspection_all.publish(String(data=self.frozen_text))
3.3 · MODULE

Cone Avoidance (YOLO + Rule)

锥桶检测 + 规则避障
FILE obstacle_avoidance/ DETECT cone_detector_yolo STRATEGY cone_strategy.py OUTPUT UDP 5005 JSON
职责拆分

YOLO 只做检测——只输出 cone 的 xyxy 框。 规则策略做决策—— cone_strategy.py 根据框中心横坐标与框面积, 生成一个保守的 vx / vy / wz。 这样的好处是可以脱离相机和机器人,做单元测试。

真实策略参数

三档前进速度:forward 0.16 / slow 0.08 / crawl 0.05。 三档转向:corridor 0.22 / avoid 0.28 / emergency 0.38。 阈值:min_confidence 0.35、 near_area_ratio 0.08、 stop_area_ratio 0.20。

真实代码
cone_strategy.py · 配置与判定 Python 
from dataclasses import dataclass

@dataclass(frozen=True)
class ConeDetection:
    xyxy:        Box            # (x1, y1, x2, y2)
    confidence:  float = 1.0
    class_name:  str   = "cone"

    @property
    def center_x(self) -> float: return (self.xyxy[0] + self.xyxy[2]) * 0.5
    @property
    def area(self) -> float:
        x1,y1,x2,y2 = self.xyxy
        return max(0.0, x2-x1) * max(0.0, y2-y1)

@dataclass(frozen=True)
class AvoidanceConfig:
    min_confidence:            float = 0.35
    near_area_ratio:           float = 0.08
    stop_area_ratio:           float = 0.20
    forward_speed:             float = 0.16
    slow_speed:                float = 0.08
    crawl_speed:               float = 0.05
    avoid_turn_speed:          float = 0.28
    emergency_turn_speed:      float = 0.38
    max_corridor_turn_speed:   float = 0.22
    gap_center_deadband_ratio: float = 0.06

3.4 · MODULE

JetArm Task Manager

机械臂任务状态机
FILE arm_grasp/ HARDWARE JetArm SDK ros_robot_controller BUILD colcon
核心设计

流程:抓红条 → 保持夹紧 → 走到放置区 → 识别目标字母 → 松爪。 关键点:不能按时间松手,只有 /placement/recognized_zone 与本次异常区匹配上, 才通过 /arm/command 让机械臂松爪。

协同节点

inspection_memory_node.py 订阅 /inspection/all, 记下异常区域列表并发布 /inspection/target_zones。 tools/inspection_pick_place_coordinator.py 等到 /mission/event = pick_area_arrived 后, 再触发 /task/start 让机械臂开始抓红条。

真实启动流程
终端 3 · 机械臂启动 Bash

# 手动模拟识别到 A 放置区(用于离线联调)

04

工程上的几个关键决策

这些是我们做过的选择,以及为什么这么选。

B1

所有感知/决策下沉到 Jetson

Lite2 狗端不跑 YOLO、不跑 OpenCV 读表、不跑 ORB-SLAM3、不跑 ROS2 状态机。 狗端只接 vx/vy/wz 或 Lite2 原生命令,并保留 watchdog。 原因:狗端算力不够且容易掉链,关键路径上任何一帧卡顿都会让 比赛直接失分。

Jetson Xavier NX UDP 5005 Lite2 watchdog
B2

状态冻结:连续 N 帧才认定

InspectionFreezer(stable_count=3) 要求每个区 连续 3 次同样的结果才冻结。全部 4 个区冻结后, 才向 /inspection/all 发布最终字符串, 机械臂才允许开始抓红条。 这一个机制杜绝了"画面刚闪过一帧 A:abnormal 就误触抓取"的问题。

N = 3 四区全部冻结 /inspection/reset 重置
B3

机械臂"保持夹紧",不按时间松爪

task_manager_node.py 只在 /placement/recognized_zone 与本次异常区匹配时, 才会发出松爪命令。这样机器人可以从容走到任意一个 字母纸箱前再决定放哪里,而不是固定几秒后被迫松手。

无定时器 /placement 触发 匹配才松爪
B4

--no-ros / --dry-run / HTTP 推流调试体系

bridge_node.py --no-ros 可以脱离 ROS2 环境跑格式验证; obstacle_zone_runner --dry-run 不连相机也能测策略; live_detect_yolo_opencv.py 同时启动 HTTP 8080 JPEG 推流, 现场笔记本用浏览器就能看到实时画面。 这套"无机器人也能调试"的链路是赛前最大的节省。

--no-ros 验证 --dry-run 策略 HTTP 8080 推流
